WSL 101

A GUI Refugee's Guide to the Terminal • Because clicking is for quitters

TL;DR

  • WSL = Linux inside Windows without dual-booting or VMs
  • Two worlds: Windows (C:\Users\...) vs Linux (/home/...)
  • Use /mnt/c/ to access your Windows files from Linux
  • Terminal commands look cryptic but are actually simple verbs
  • You can break things, but mostly just in your Linux world

What The Hell Is WSL Anyway?

WSL (Windows Subsystem for Linux) is Microsoft's love letter to developers who got tired of rebooting into Ubuntu. It's a real Linux kernel running inside Windows 11. Not a VM, not a compatibility layer—actual Linux. You can run apt install, compile code, use bash scripts, and pretend you're a real hacker, all while Outlook and Edge are still running in the background.

Think of it like this: Windows is the building, WSL is an apartment inside it. The apartment has its own interior (Linux filesystem), but you can still access the building's facilities (your Windows files and apps).

Why you care: Modern dev tools (like Claude Code) are built for Unix-like systems. WSL lets you use them without abandoning Windows. Plus you look cooler typing in a terminal than clicking through GUIs.

Official docs: Microsoft WSL Documentation

The Two-World Problem

Here's the mindfuck that nobody explains well: you now have TWO filesystems.

World Where Files Live Accessible From
Windows C:\Users\YourName\ File Explorer, Windows apps, WSL via /mnt/c/
Linux (WSL) /home/yourname/ Terminal, Linux apps, Windows via \\wsl$\
Critical: Files in your Linux home directory (/home/yourname/) are NOT in your Windows Documents folder. They're in a hidden location that Windows manages. Don't edit Linux files with Windows apps unless you know what you're doing—file permissions get weird.

Where Should I Put My Stuff?

🌞 Light Side (Safe)

Windows side for:

  • Documents you edit in Word/Excel
  • Files you need in OneDrive
  • Anything you access from Windows apps

Access from Linux:
/mnt/c/Users/YourName/Documents/

🌙 Dark Side (Fast)

Linux side for:

  • Code projects (way faster)
  • Node modules, build outputs
  • Anything only Linux tools touch

Access from Windows:
\\wsl$\Ubuntu\home\yourname\

Pro move: Keep code in ~/projects/ (Linux) for speed, but symlink to Windows for backups if needed.

Terminal Basics: The Essential Verbs

The terminal is just a text-based way to tell your computer what to do. Instead of clicking folders, you type where to go. Here are the commands you'll use 80% of the time:

Navigation (Moving Around)

$ pwd
# Print Working Directory - where am I right now?
/home/yourname
$ ls
# List - show me what's here (like viewing folder contents)
projects documents downloads
$ ls -la
# List with ALL details and hidden files (the good stuff)
drwxr-xr-x 5 yourname yourname 4096 Jan 21 10:30 . drwxr-xr-x 3 root root 4096 Jan 15 08:00 .. -rw-r--r-- 1 yourname yourname 220 Jan 15 08:00 .bashrc drwxr-xr-x 2 yourname yourname 4096 Jan 20 14:22 projects
$ cd projects
# Change Directory - go to the 'projects' folder
$ cd ..
# Go up one level (parent directory)
$ cd ~
# Go home - back to /home/yourname/
Tab completion is magic: Type the first few letters of a file/folder name and hit TAB. The terminal autocompletes it. Hit TAB twice to see all options. This alone will 10x your speed.

File Operations

$ mkdir my-project
# Make Directory - create a new folder
$ touch readme.md
# Create an empty file
$ cp file.txt backup.txt
# Copy file.txt to backup.txt
$ mv old.txt new.txt
# Move/rename - works for moving AND renaming
$ rm file.txt
# Remove - delete a file (CAREFUL: no recycle bin!)
There is no Ctrl+Z for rm: Deleted files are GONE. If you're nervous, use rm -i file.txt to get prompted before deletion. Or just move files to a trash folder first.

Viewing Files

$ cat file.txt
# Show entire file contents in terminal
$ less file.txt
# View file page-by-page (q to quit, space to scroll)
$ head -n 20 file.txt
# Show first 20 lines
$ tail -f log.txt
# Show last lines and follow updates (great for logs)

Package Management: Installing Stuff

In Windows you download .exe files or use Microsoft Store. In Linux (Ubuntu specifically, which WSL defaults to), you use apt (Advanced Package Tool).

$ sudo apt update
# Update package list (like refreshing the app store)
$ sudo apt upgrade
# Upgrade installed packages to latest versions
$ sudo apt install git
# Install git (or any package)

What's sudo? It means "Super User DO" - basically "run this as admin". Linux asks for permission before changing system stuff. You'll type your password (which won't show as you type—that's normal, just trust and hit Enter).

Common installs for dev work:
  • sudo apt install git - version control
  • sudo apt install curl - download stuff from URLs
  • sudo apt install build-essential - C/C++ compilers
  • sudo apt install python3 python3-pip - Python

Node.js? Use nvm (Node Version Manager) instead of apt—it's way better for managing versions.

Running Claude Code (And Other Tools)

This is probably why you're here. Tools like Claude Code expect a Unix environment. Here's the basic flow:

1. Install the tool (usually via npm or direct download)

$ npm install -g @anthropic-ai/claude-code
# Install Claude Code globally

2. Navigate to where you want to work

$ cd ~/projects/my-app
# Or wherever your code lives

3. Run the tool

$ claude-code
# Launches Claude Code in current directory
Pro tip: Add an alias to your .bashrc or .zshrc for quick access: 
alias cc='claude-code'
Then just type cc to launch.

Common Gotchas & How to Fix Them

❌ "Command not found"

The tool isn't installed, or it's not in your PATH (the list of places the terminal looks for commands).

Fix: Install it, or add its location to PATH. For global npm packages, make sure npm's global bin is in your PATH.

❌ "Permission denied"

You're trying to do something that needs admin rights.

Fix: Add sudo before the command. Or check file permissions with ls -la.

❌ Files changed in Windows don't show in Linux (or vice versa)

You're looking in the wrong filesystem. Remember: Windows files are at /mnt/c/, Linux files are at /home/yourname/.

Fix: Use pwd to check where you actually are.

❌ Slow file operations when working in /mnt/c/

Cross-filesystem access (Windows ↔ Linux) is slower than native.

Fix: Keep projects in ~/projects/ (Linux native) for speed.

❌ "No such file or directory" but I can SEE the file

Linux is case-sensitive. File.txt ≠ file.txt.

Fix: Check exact spelling and capitalization.

The Dark Arts: Pipes, Redirects & Chaining

Once you're comfortable with basics, these make you dangerously efficient.

Pipes (|)

Send output of one command into another:

ls -la | grep ".json"
# List files, filter for .json
cat log.txt | tail -n 50
# Show last 50 lines of log

Redirects (> >>)

Save output to a file:

ls -la > files.txt
# Save list to file (overwrites)
echo "new line" >> log.txt
# Append to file
$ command1 && command2
# Run command2 only if command1 succeeds
$ npm install && npm run build
# Install packages, then build (if install worked)

Keyboard Shortcuts That Save Your Sanity

Shortcut What It Does
Ctrl + C Kill current command (stop it running)
Ctrl + D Exit current shell/program
Ctrl + L Clear screen (same as clear)
Ctrl + A Jump to start of line
Ctrl + E Jump to end of line
Ctrl + R Search command history (reverse search)
↑ / ↓ Cycle through previous commands
Tab Autocomplete file/folder/command names

Your First Day Checklist

  1. Create a projects folder: mkdir ~/projects && cd ~/projects
  2. Update the system: sudo apt update && sudo apt upgrade
  3. Install essentials: sudo apt install git curl build-essential
  4. Set up SSH keys (for GitHub etc): GitHub SSH Guide
  5. Configure git: git config --global user.name "Your Name" and git config --global user.email "you@example.com"
  6. Install Node via nvm: nvm installation
  7. Customize your shell: Edit ~/.bashrc or switch to Oh My Zsh for better defaults

Final Thoughts

The terminal feels weird at first because you can't see what you're doing. But that's also its power—text is fast, scriptable, and doesn't care about your screen resolution. You'll fumble for a week, then suddenly realize you're navigating faster than in File Explorer.

Plus, now when someone says "just run npm install" or "check the logs with tail -f", you'll know exactly what they mean instead of frantically Googling.

Remember: The terminal won't explode if you make a mistake. The worst you'll do is delete some files (which you should be backing up anyway). Just don't blindly paste commands from Reddit without reading them first—that's how people accidentally sudo rm -rf / their entire system.
