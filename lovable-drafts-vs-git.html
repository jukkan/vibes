Drafts vs Git

Lovable did not invent a new version-control idea. It translated a familiar Git workflow into the language of trying, updating, accepting and publishing.

“

Git describes what happens to history. Drafts describe what the person is trying to do.

01 · Same journey

Two vocabularies for the same basic workflow

Classic Git
implementation language
  1. Create a branchgit switch -c redesign — split off a separate line of work.
  2. Edit + commitChange files and record snapshots while the main branch stays untouched.
  3. Rebase / resolveBring newer main-branch changes underneath your work; resolve overlapping edits.
  4. MergeIntegrate the branch back into the main history.
  5. DeployA separate delivery step makes the merged version live.
Lovable Drafts
intent language
  1. New Draft“I want to try something without changing Main.”
  2. Chat + buildThe draft gets its own conversation, preview and edits.
  3. Update“Bring in what changed since I started.” Lovable handles overlapping edits.
  4. Accept“Keep this idea.” The edits become part of Main's unpublished changes.
  5. PublishOnly now does the accepted version reach the live app.

03 · Similarities

The abstraction works because the underlying ideas really are the same

01 / ISOLATE

Work separately

Main does not receive your draft edits until you deliberately integrate them.

02 / SYNC

Catch up later

A draft can incorporate newer Main changes before it is accepted.

03 / CHOOSE

Keep or discard

Experiments are cheap: accept the useful one, delete the dead end.

04 / HISTORY

Preserve a timeline

Accepted work becomes part of project history rather than overwriting Main invisibly.

04 · Differences

A Draft is more — and currently less — than a Git branch

More

The conversation travels with the experiment

A Draft has its own AI chat, preview and edits. A Git branch normally knows about files and history, not the reasoning conversation that produced them.

Less

Open Drafts are not Git-synced branches

In the current beta, Drafts do not sync directly to GitHub or GitLab. Accepted edits later sync to the connected repository like other project changes.

Boundary

Frontend only, for now

The first release targets layout, styling and copy. Database structure, login setup and enabling Lovable Cloud still happen in Main.

Gotcha

The data is not a draft

The preview still uses the project's real backend data. Add, edit or delete records while testing and those data changes are real.

06 · The point

Git can remain the substrate without being the user interface.

Drafts are a good example of AI-era tooling moving one level up the abstraction stack. The underlying version-control mechanics still matter, but the builder can increasingly express decisions rather than operations.

For someone who understands the value of Git but never found its terminology natural, that is not merely cosmetic. It is a better match between the tool's language and the human's intent.
